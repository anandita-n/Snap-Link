# AI Triage Report Examples

This directory contains real, verified examples of structured JSON triage reports generated by the Jenkins pipeline's AI Analysis stage using `gemini-3.5-flash`.

## Included Scenarios

1. **Backend Unit Test Failure**:
   * File: [triage_report_backend_failure.json](triage_report_backend_failure.json)
   * Triggered by setting `TOGGLE_TEST_FAILURE = 'true'` in the `Jenkinsfile`.
   * Real report identifying the intentional failure in `backend/tests/test_logic.py`.

2. **Frontend Test Failure**:
   * File: [triage_report_frontend_failure.json](triage_report_frontend_failure.json)
   * Triggered by setting `VITE_TOGGLE_TEST_FAILURE = 'true'` in the `Jenkinsfile`.
   * Real report identifying the component test failure in `frontend/src/tests/App.test.jsx`.

3. **API Key / Credential Failure (Fallback Guardrail)**:
   * File: [triage_report_invalid_key_fallback.json](triage_report_invalid_key_fallback.json)
   * Triggered when the `GEMINI_API_KEY` environment variable is invalid or missing, or in case of transient API failures.
   * Demonstrates the fallback report that adheres strictly to the `TriageReport` Pydantic schema without crashing the build.

## Clean Build Scenario
A **clean, passing build** intentionally produces **no** `triage_report.json` artifact at all. When tests and lints pass successfully, the `AI Analysis` stage in the `Jenkinsfile` is skipped via conditional logic, and any stale reports from previous runs are cleaned up at the start of the build.
